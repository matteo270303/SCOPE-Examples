# CHAIN-OF-THOUGHT REASONING SEQUENCE
You MUST follow this reasoning order, which mirrors the natural dependency chain in three-tier architectures:

Step 1 — DATA MODEL AND ENTITY RELATIONSHIPS: Define all database entities, their attributes, and how they relate to each other. Every entity referenced in the requirements must appear here. Specify: table names, column names with data types, primary keys, foreign keys with cascade behavior, unique constraints, and indexes.

Step 2 — BACKEND API ARCHITECTURE: Design the backend structure around the entities defined in Step 1. Group related functionalities into logical modules (Blueprints in Flask). For each module, specify: the endpoints it exposes (HTTP method, route, purpose), the authentication requirements, the request/response format, and which database entities it operates on. Every functional requirement tagged as "backend" must map to at least one endpoint.

Step 3 — FRONTEND PAGE AND COMPONENT DESIGN: Determine the frontend pages that consume the API endpoints defined in Step 2. For each page, specify: the route, the data it fetches (which endpoints), the components it uses, the user interactions it supports, and whether it is public or protected. Every functional requirement tagged as "frontend" must map to at least one page or component.

Step 4 — FILE SYSTEM LAYOUT: Specify the complete directory hierarchy and every file in the project. For each file, provide: the path, the purpose, and the key contents (e.g., which entities a model file defines, which endpoints a route file exposes, which components a page file renders).

### 1. Data Model and Entity Relationships

The application uses MySQL with four core entities:

**Users**: Stores administrator accounts. Fields: id (INT, PK, AUTO_INCREMENT), username (VARCHAR(50), UNIQUE, NOT NULL), email (VARCHAR(100), UNIQUE, NOT NULL), password_hash (VARCHAR(255), NOT NULL), created_at (DATETIME, DEFAULT CURRENT_TIMESTAMP). One user owns many articles (1:N with Articles).

**Categories**: Organizes articles by topic. Fields: id (INT, PK, AUTO_INCREMENT), name (VARCHAR(100), UNIQUE, NOT NULL), slug (VARCHAR(100), UNIQUE, NOT NULL). One category contains many articles (1:N with Articles).

**Articles**: Core content entity. Fields: id (INT, PK, AUTO_INCREMENT), title (VARCHAR(200), NOT NULL), slug (VARCHAR(200), UNIQUE, NOT NULL), content (TEXT, NOT NULL), excerpt (VARCHAR(500)), featured_image (VARCHAR(255)), status (ENUM('draft','published'), DEFAULT 'draft'), author_id (INT, FK → Users.id, ON DELETE CASCADE), category_id (INT, FK → Categories.id, ON DELETE SET NULL), created_at (DATETIME), updated_at (DATETIME). Indexes on slug, status, category_id, author_id.

**Comments**: Visitor interactions on articles. Fields: id (INT, PK, AUTO_INCREMENT), article_id (INT, FK → Articles.id, ON DELETE CASCADE), author_name (VARCHAR(100), NOT NULL), author_email (VARCHAR(100)), body (TEXT, NOT NULL), created_at (DATETIME, DEFAULT CURRENT_TIMESTAMP). Index on article_id.

### 2. Backend API Architecture (Flask)

The backend is organized into four Blueprints:

**Auth Blueprint** (REQ-BE-001): Handles administrator authentication.
- POST /api/auth/register — Creates a new admin account. Accepts: {username, email, password}. Returns: 201 with user object. Hashes password with bcrypt.
- POST /api/auth/login — Authenticates an admin. Accepts: {email, password}. Returns: 200 with JWT access token (1h expiry) and refresh token. JWT stored in HTTP-only cookie.

**Articles Blueprint** (REQ-BE-002): Full CRUD for articles.
- GET /api/articles — Public. Returns paginated list of published articles. Query params: page, per_page, category_id. Response: {articles: [...], total, page, pages}.
- GET /api/articles/<slug> — Public. Returns single article with comments.
- POST /api/articles — Admin only (JWT required). Creates article with auto-generated slug from title.
- PUT /api/articles/<id> — Admin only. Updates article fields.
- DELETE /api/articles/<id> — Admin only. Deletes article and cascading comments.

**Categories Blueprint** (REQ-BE-004): Category management.
- GET /api/categories — Public. Returns all categories.
- POST /api/categories — Admin only. Creates category with auto-slug.
- PUT /api/categories/<id> — Admin only. Updates category.
- DELETE /api/categories/<id> — Admin only. Deletes category, articles set to NULL category.

**Comments Blueprint** (REQ-BE-003): Comment management.
- GET /api/articles/<id>/comments — Public. Returns comments for an article.
- POST /api/articles/<id>/comments — Public. Creates comment. Accepts: {author_name, author_email, body}. Input sanitized against XSS.

All endpoints return JSON with consistent error format: {error: string, status: int}. CORS configured for frontend origin.

### 3. Frontend Pages and Components (Next.js + React + Tailwind CSS)

**Public pages:**
- Home page (/) (REQ-FE-001): Displays grid of ArticleCard components for published articles. Category filter sidebar. Pagination controls. Fetches GET /api/articles and GET /api/categories.
- Article detail page (/articles/[slug]) (REQ-FE-002): Renders full article content, author, date. CommentList component showing existing comments. CommentForm component for submission. Fetches GET /api/articles/<slug>.
- Category page (/categories/[slug]): Filtered article list. Fetches GET /api/articles?category_id=X.

**Protected admin pages (require JWT):**
- Login page (/admin/login) (REQ-FE-005): Email/password form. Error feedback. Redirects to dashboard on success.
- Dashboard (/admin/dashboard) (REQ-FE-003): Article count, recent comments, quick action buttons.
- Article editor (/admin/articles/new, /admin/articles/[id]/edit) (REQ-FE-004): Form with title, content textarea, category select, image upload, draft/publish toggle. Client-side validation.
- Category manager (/admin/categories): List with inline edit/delete. Create form.

**Reusable components:** Header (navigation, conditional admin link), ArticleCard (title, excerpt, category, date, image), CommentForm (validated inputs), CommentList, Pagination, ProtectedRoute (HOC, redirects to login if no JWT).
